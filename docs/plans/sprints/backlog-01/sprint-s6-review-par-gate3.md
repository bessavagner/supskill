## Sprint goal (one line)

> `/supskill run <sprint>` at stage REVIEW drives a G2-approved, executed branch to a closed sprint: two adversarial reviewers score it under a fixed aggregation rule that always takes the worse severity, Gate 3 presents that plus E5's blocker/concern batch as one decision, the operator's answer resolves into exactly one of four replan shapes — never a fifth, never a silent north-star reset — and the conductor proposes the next sprint and stops.

## Why this sprint

E6 is the epic the backlog itself calls highest value, highest complexity, and it is the one every other epic has been building toward: E1's spine can record a status, E5's drain can produce one, and nothing yet closes the loop by *judging* what got produced. F-5 is the reason a single reviewer cannot be that judge — blinkebot's S9 shipped green, 410 tests passing, and its own whole-branch review still found five mechanisms wired into nothing. A self-certifying agent reporting confidently on mediocre work is not a hypothetical failure mode in this project's own history; it is the fixture. D9's answer — two reviewers on identical input, a competitive frame ("false positives are worse than misses"), and a fixed rule that always takes the worse severity on disagreement — is stolen rather than reinvented, per invariant 1's compose-never-reinvent floor.

Gate 3 is where the product's whole thesis gets tested a third time: the script enforces the precondition (`G3_review` has existed, unused, since S1, `scripts/supskill_state/model.py:59`), but the *quality* of what reaches the operator is still a prompting problem, same as G1 and G2 were. The difference this time is the join — Gate 3 is the first gate that must merge two independently-produced batches (E5's blockers/concerns, SK-050's aggregated findings) into one legible question, and the backlog's own finding F-4 stands: the script cannot prove a human answered, it can only make skipping loud and auditable.

The two remaining stories are where the backlog's inviolable invariants stop being abstractions. Invariant 7 — "the conductor never supersedes a backlog on its own" — has exactly one story whose entire job is to make that literally true rather than aspirationally true (SK-053). And D6 — "one sprint per invocation" — has exactly one story whose entire job is to make the conductor stop talking once it has proposed what comes next (SK-054), rather than trusting the model's own momentum not to keep going.

**This document has now been refined at pull time** — read against the live source under `scripts/supskill_state/`, `skills/supskill/SKILL.md`, `scripts/supskill-audit`, and the design decisions doc, the same pass E3's SK-021 runs for every sprint. Every prior sprint's REFINE pass grew its committed points (10→16, 14→16, 18→23, 19→23), and this one is no exception: E6 goes 23 → 27. The sharpest findings this time are not defects the way S5's were — E6's code does not exist yet, so there was nothing to be silently broken — but they are still things the backlog's one-liner could not know: two of the five stories name a verb and a prompt template that must be built from nothing (SK-050), and one names a CLI value the live schema refuses outright today (SK-051). Where this pass still had to make a call the backlog's one-liners did not settle, it took the smaller, reversible default and recorded the call in the [DoR findings](#dor-findings-refined-at-pull-time) and risks table below — Gate 1 is where the operator overrules it.

## Stories

### SK-050 — PAR: two adversarial reviewers, worse severity wins · 11 · M · **(8 → 11 at pull time)**

- **As** Gate 3, **I want** two reviewer subagents scoring the executed branch under a fixed competitive frame and a fixed aggregation rule, **so that** a single reviewer's sycophancy (F-5) is never the sprint's only signal.
- **proof:** seam=app-level · impact=journey · provable=operator *(the aggregation rule itself — same finding both ⇒ high confidence, found by one only ⇒ still actionable, severity disagreement ⇒ always the worse — is a pure function of two finding lists, now embodied as the new `review` verb's refusals, and is this story's offline-TDD'able slice; the two dispatches and the quality of what they find are not)*

- **Context.** D9 names the mechanism precisely (`contexts/06`): dispatch two reviewer subagents on identical input, wrapped in a fixed competitive-scoring frame — *"false positives are worse than misses"* — and aggregate by fixed rule, no negotiation. "Identical input" needs no new diff mechanism, and it does not even need re-deriving: EXECUTE already produces it and leaves it on disk. SK-040's own accept criteria has the conductor run `review-package $(git merge-base <default-branch> HEAD) HEAD <scratch>/review-final.diff` as its last act before halting (`skills/supskill/SKILL.md:344-347`), and the halt section names the file explicitly as the handoff to this stage: *"Your job is to leave `<scratch>/review-final.diff` and the `--note` roll-ups **on disk** for E6's REVIEW/PAR stage to read"* (`skills/supskill/SKILL.md:472-475`). PAR's two dispatches read that one file — there is nothing left for REVIEW to compute before dispatching.

  Two things the backlog's row could not see, because neither has ever been built. **First: no verb writes a review finding.** `cli.py`'s full subcommand list is `init | show | artifact | gate | block | task | tasks | advance | plan-guard | cost` (`scripts/supskill_state/cli.py:21-30`) — the same closed enumeration whose missing `task` entry was S5's sharpest finding. There is no finding shape in `model.py`, no writer function in `commands.py`, and no `runs/<id>/review.jsonl` anywhere, unlike `blockers.jsonl` (`scripts/supskill_state/commands.py:256-269`), `tasks.jsonl` (`scripts/supskill_state/commands.py:380-386`) and `costs.jsonl` (`scripts/supskill_state/commands.py:422-434`), which each have one. "Aggregated findings are written to disk" is not yet a fact about this codebase; making it one is this story's job. **Second: PAR has no prompt template, and unlike EXECUTE this is not optional.** EXECUTE composes SDD's own implementer/task-reviewer prompts verbatim and supplies none of its own — `tests/test_execute_prose.py:82` asserts `references/execute-prompt.md` does not exist. PAR is different: D9 steals it from `iterative-development` as a *mechanism*, not an invocable skill, so there is no installed skill to hand this dispatch to. `test_prompt_templates.py`'s own template tuple is `(SCOPE, REFINE, PLAN)` (`tests/test_prompt_templates.py:14`) — three, not four. REVIEW is the first stage since REFINE that needs a genuinely new template, and it needs one dispatched **twice**, with no cross-visibility between the two runs — the competitive frame's entire point.

- **Accept:**
  - Two reviewer subagents (`reviewer-a`, `reviewer-b`) dispatched on the identical `<scratch>/review-final.diff` package; neither sees the other's output; each returns a structured finding list — severity, description, location. A new template, `skills/supskill/references/review-prompt.md`, filled once per dispatch with `{REVIEWER_LABEL}` (`reviewer-a` or `reviewer-b`), `{REVIEW_PACKAGE_PATH}` (`<scratch>/review-final.diff`), `{REPO_ROOT}`, and the same two standing constraints every existing template states verbatim — "cannot ask anyone anything" and "must not run `supskill-state`" (`tests/test_prompt_templates.py:26-27`, `:55-56` — the pattern this template's own test extends). `test_prompt_templates.py`'s `TEMPLATES` tuple (`tests/test_prompt_templates.py:14`) grows to four.
  - Fixed aggregation, stated as a rule with no override: same finding reported by both → `confidence=high`; found by one reviewer only → `confidence=actionable`, listed as such; the same finding at different severities from the two reviewers → the worse severity wins, always, ranked `Critical > Important > Minor` — the exact three-level vocabulary this repo already imported from SDD for EXECUTE's fix trigger and roll-up (`skills/supskill/SKILL.md:384-385`, `:393`), now given its first Python home. **Matching** which finding from `reviewer-a` corresponds to which from `reviewer-b` is the conductor's judgment, not a string comparison — this prose does not pretend otherwise, exactly as SK-041 said the same of "same root cause." Only the already-matched severity comparison is the pure, offline-TDD'able function this story's proof line names.
  - A new CLI verb, modeled on `record_blocker`'s validate-then-write shape (`scripts/supskill_state/commands.py:219-272`): `supskill-state review --reviewer <reviewer-a|reviewer-b|both> --severity <Critical|Important|Minor> --confidence <high|actionable> --finding "<description>" --location "<file:line or path>"`. Non-empty `--finding`/`--location`, mirroring the per-flag check `record_blocker` already runs (`scripts/supskill_state/commands.py:229-231`); an unknown `--severity` or `--confidence` token refused by the vocabulary's own owner, mirroring `parse_task_status`'s pattern of the model raising its own message (`scripts/supskill_state/model.py:133-146`). Each record is appended **trail-first** to `runs/<id>/review.jsonl` via `store.append_jsonl` (`scripts/supskill_state/store.py:64-70`), timestamped with `store.now_utc_iso()` (`scripts/supskill_state/store.py:73-74`) — the sibling of `blockers.jsonl`/`tasks.jsonl`/`costs.jsonl`, built the same way. No `state.json` schema bump: like `costs.jsonl` (`scripts/supskill_state/commands.py:390-434`), this verb reads `state.json` only to place the trail file by `sprint.id` and writes nothing back to it.
  - Every dispatch names its model explicitly (the discipline SK-040 established for SDD dispatches) and logs its usage via the existing `cost --stage REVIEW --label reviewer-a|reviewer-b` verb — built in commit `fcc78f7` for exactly this question.
  - Aggregated findings land in `runs/<id>/review.jsonl` before Gate 3 opens — the smaller, reversible default (no `state.json` schema bump unless a later pass finds the trail insufficient — the same reversibility SK-043 used for concerns).
  - No dispatched reviewer runs `supskill-state` — the standing invariant-3 check, extended a fourth time (SCOPE/PLAN's templates, EXECUTE's implementers, now REVIEW's reviewers).

### SK-051 — Gate 3: one decision, not two · 4 · M · **(3 → 4 at pull time)**

- **As** the operator, **I want** the sprint's blockers, parked tasks, concerns, and PAR's aggregated findings presented as a single question, **so that** closing a sprint is one high-information decision instead of a stall, or a second gate I have to notice exists.
- **proof:** seam=app-level · impact=journey · provable=operator

- **Context.** The CLI enforcement mostly already exists: `GATE_KEYS` has carried `"G3": "G3_review"` since S1 (`scripts/supskill_state/model.py:59`), and the `gate` subparser's `--id` already accepts `G3` (`scripts/supskill_state/cli.py:91`) — the generic `gate` verb built for G1/G2 needs no new plumbing for the gate *mechanism*. This story, like SK-032's Gate 2, is mostly the UX and the batching. What is new is the join: Gate 3 is the first gate that must merge two independently-produced batches (E5's halt-report data — blockers with options/recommend, parked tasks, `DONE_WITH_CONCERNS` notes — and SK-050's aggregated PAR findings) into one legible question, and nothing may fall off the edge because it scrolled past.

  One thing is missing, and it is not cosmetic. `--decision` has exactly two legal values today, `("approved", "rejected")` (`scripts/supskill_state/model.py:61`), enforced identically in `cli.py`'s `choices=["approved", "rejected"]` (`scripts/supskill_state/cli.py:92`) and in `_parse_gates`' load-time validation (`scripts/supskill_state/model.py:174-178`). A `gate --id G3 --decision replan` call, as this row was first going to specify it, is refused today with `unknown decision 'replan'; expected one of ['approved', 'rejected']` (`scripts/supskill_state/commands.py:200-201`). This is not an oversight to route around — S1's own sprint doc named it as a deliberate deferral: *"The decision vocabulary is deliberately minimal — G3's four replan shapes are E6's to add"* (`docs/plans/sprints/backlog-01/sprint-01-state-spine.md:104`). This story is where that IOU is paid: `GATE_DECISIONS` grows to `("approved", "rejected", "replan")`, a one-line, additive change in `model.py:61` plus the matching `choices` list in `cli.py:92`; `_parse_gates` needs no further change, since it already validates against the tuple generically (`scripts/supskill_state/model.py:174-178`).

- **Accept:**
  - One real `AskUserQuestion`, not simulated. The question body enumerates every open blocker (with its options and recommendation), every parked task (with the blocker that parked it), every `DONE_WITH_CONCERNS` note verbatim, and every PAR finding at `confidence=high` or `confidence=actionable` from `runs/<id>/review.jsonl` — the union of both batches, nothing silently dropped.
  - An empty or auto-resolved answer is not a decision — the standing Gate 1/2 rule, copied a third time. Sprint-04 named the third instance as the trigger to extract a shared `references/gate.md`: *"If a third repetition of this block starts to itch at E6, that is the signal... two instances is a coincidence, three is a pattern"* (`docs/plans/sprints/backlog-01/sprint-04-plan-gate2.md:67`). This story is where that extraction happens.
  - A non-empty answer that closes the sprint cleanly, with none of the three amending shapes needed → `gate --id G3 --decision approved --response "<verbatim>"`. An answer that resolves into any of Shapes 1–3 (SK-052) → `gate --id G3 --decision replan --response "<verbatim>"`, and the conductor then runs whichever shape-specific verb applies — the `--decision` records only that the operator chose *some* amendment, never which of the three; that distinction lives in the response text and in which verb runs next. Shape 4 (SK-053) is **never** a value this verb accepts or records: the refusal happens before any `gate` call, so a north-star-reset reading of the operator's answer produces a report, not a decision.

### SK-052 — The four replan shapes, incl. generative writeback · 8 · M · **(8 → 8 at pull time — gained citations and one restraint, not scope)**

- **As** the operator closing a sprint, **I want** my Gate 3 answer to land in exactly one of four defined outcomes, **so that** "amend the backlog" is never ad hoc, and generative writeback is a rule rather than an improvisation.
- **proof:** seam=app-level · impact=journey · provable=operator

- **Context.** The backlog's row names "the four replan shapes, incl. generative writeback" without listing all four; the authoritative list is design-decisions.md's own table (lines 244–254), carried forward here rather than re-derived: *review generates new items* (S9 → S9a — appends new `pending` rows); *execution stops at a live boundary* (S9a — parks a task, sprint stays open); *live evidence overturns the diagnosis* (S9a → S9b — forks a new sprint and, where warranted, a branch rename, with the operator ruling on process weight before any code moves); *north-star reset* (backlog-01 → 02 — supersedes the whole backlog). The first three **amend**; the fourth **replaces** and is refused here by construction — that refusal is SK-053's entire story, not a missing branch in this one.

  Direct `backlog.md` edits are already this project's own practice, not a new capability this story invents: every prior sprint's own "Backlog deltas — proposed" section has been applied by hand, outside `supskill-state`, in its own `docs:` commit (`ec22e25`, `62fd0dc`, `133da28`). Invariant 3 binds `state.json` specifically — *"The script is the only mutator of `state.json`"* (`docs/plans/sprints/backlog-01/backlog.md:29-30`) — and `backlog.md` was never inside that boundary.

- **Accept:**
  - **Shape 1 — generative writeback:** new rows appended to `backlog.md` under the relevant epic (or a new epic, if none fits), in the existing row format (`| ID | Story | Pts | Pri | Status |`, `backlog.md:84`, status `☐`), each citing the PAR finding or blocker that motivated it. The conductor only appends — it never edits an existing row's points or status here (that is a backlog-delta ritual owned by the sprint that actually implements the change, per every prior sprint's own "Backlog deltas — proposed" section).
  - **Shape 2 — park at a live boundary:** the unfinished task stays `PARKED` in `state.json` via the verb that already exists, `task --id <SK-0xx> --status PARKED --note "<...>"` (`scripts/supskill_state/commands.py:331-387`; `--note` on `PARKED` names the blocker that parked the task, the exact convention SK-041 documented at `scripts/supskill_state/cli.py:136-140`); the sprint itself is **not** advanced past REVIEW; the report names which live boundary stopped it.
  - **Shape 3 — fork on live evidence:** the conductor drafts a forked sprint id (and a branch-rename recommendation, where warranted) but does not execute either unasked — the operator rules on the fork's process weight first, exactly as the S9a → S9b precedent requires. A fork's `init` is the verb that already exists (`scripts/supskill_state/commands.py:39-90`); a branch rename is not a verb at all, and this story does not add one — it is the same restraint EXECUTE's own branch check already states: *"Do not create, switch, or delete a branch yourself"* (`skills/supskill/SKILL.md:312-313`). The conductor names the rename without running it.
  - **Shape 4 — north-star reset:** out of scope for this story by design; SK-052 contains no code path that supersedes `backlog.md` wholesale.
  - Every shape's outcome is recorded through verbs that already exist — a `backlog.md` edit, `task --status PARKED`, a fresh `init` for a forked sprint — never a new mutator. SK-052 composes; it does not invent a fifth way to touch state.

### SK-053 — Refuse the north-star supersede · 2 · M

- **As** the backlog's author, **I want** the conductor structurally unable to replace `backlog.md`'s north star on its own, **so that** the one truly destructive replan shape always waits for me — full stop.
- **proof:** seam=unit · impact=local · provable=offline *(a refusal on a fixed classification is a pure guard, the same shape as `plan_guard.py`'s HEAD-moved check — TDD'd without an LLM)*

- **Context.** Invariant 7 states this without qualification: *"the conductor never supersedes a backlog on its own — a north-star reset is operator-authored, full stop."* Design-decisions.md draws the same line: shapes 1–3 amend, shape 4 replaces. The backlog gives no procedure for *detecting* a shape-4-shaped Gate 3 answer, so this story takes the smaller, reversible path: it does not try to classify intent, it removes the capability.

  The structural half of this claim already holds today, for free. `state.backlog` is assigned exactly once in the entire codebase, inside `init_sprint` (`scripts/supskill_state/commands.py:74-90`), and every other verb in `cli.py`'s closed subcommand list — `init | show | artifact | gate | block | task | tasks | advance | plan-guard | cost` (`scripts/supskill_state/cli.py:21-30`) — either never touches `state.backlog` or, in `init`'s own `--archive` path, only *archives* the prior state file rather than repointing the live one (`scripts/supskill_state/commands.py:93-110`). No verb anywhere edits `backlog.md`'s prose at all — the only thing that has ever changed that file is a person, by hand, in a `docs:` commit (`ec22e25`, `62fd0dc`, `133da28`). This story's actual work, then, is not building a new protection; it is the guard function itself — a pure classifier that names a shape-4 reading and refuses to act on it — plus wiring its call site into the REVIEW section, the same pairing `plan_guard.head_moved` (`scripts/supskill_state/plan_guard.py:21-29`) already has with its own call site at PLAN step 6 (`skills/supskill/SKILL.md:216-224`).

- **Accept:**
  - No code path in E6 can rewrite `backlog.md`'s `## North star` section or change `state.json.backlog` to a different path. If a Gate 3 answer reads as "supersede the backlog," the conductor names that reading in its report and stops — it drafts nothing and executes nothing.
  - A guard function, TDD'd offline: given a replan classification, refuse — loudly, not silently — any classification that would supersede rather than amend. Same shape as `plan_guard.py`'s `head_moved` predicate: a pure check plus a call site that reports and stops.
  - The refusal text names the operator's actual move: author the new backlog by hand (or with whatever process produced backlog-01), then start the next sprint against it. The conductor does not offer to do this "for convenience" — that offer is the invariant it exists to prevent.
  - A regression test asserts the structural claim continues to hold: no function outside `init_sprint` assigns `state.backlog`, and no CLI subcommand writes to a `.md` file — the same closed-enumeration check SK-052's own accept criteria relies on.

### SK-054 — Propose the next sprint, then stop · 2 · M

- **As** the operator, **I want** the conductor to name what it would pull next and then actually stop, **so that** "one sprint per invocation" (D6) is a guarantee, not a suggestion the model might relax under its own momentum.
- **proof:** seam=app-level · impact=local · provable=operator *(the proposal's content is generative, judged by the operator; that the conductor halts after it and issues no further dispatch is a mechanical, offline-checkable guarantee)*

- **Context.** D6: *"v1 runs exactly one sprint per invocation. Plans go stale. No look-ahead planning."* This story is the sprint's last mile: once a replan shape (SK-052 or the SK-053 refusal) has resolved the sprint, the conductor reads the backlog's build order for the next epic whose stories are still unchecked — the same rule this very document's dispatcher used to select E6 — and names it: epic, backlog points, one sentence why.   One structural backstop already exists for free. `Stage.REVIEW` is the last entry in `STAGE_ORDER` (`scripts/supskill_state/model.py:34-40`), so `next_stage(Stage.REVIEW)` returns `None` (`scripts/supskill_state/transitions.py:20-24`) and `advance_stage` refuses any `--to` at all from REVIEW with *"REVIEW is the final stage; there is nothing to advance to"* (`scripts/supskill_state/commands.py:446-448`). The state machine cannot advance past REVIEW even if the conductor tried. The mechanical check this story needs is the same shape as the standing invariant-3 check already shipped for EXECUTE (`tests/test_execute_prose.py:37-42`, asserting no stub language survives) — a static assertion against the REVIEW section's own prose, not a live transcript replay. That the conductor actually obeys the prose in a real run is `provable=operator`, correctly, and this story's proof line already says so.

- **Accept:**
  - The proposal is prose, not a dispatch: it names the next epic in build order, its backlog points, and why — the same three facts this doc's own header line carries for E6.
