## Sprint goal (one line)

> `/supskill run <sprint>` at stage EXECUTE drives a G2-approved dev plan to a halt the operator can act on: every drainable task is implemented and reviewed through `subagent-driven-development`, each task's SDD status is written to `state.json` the moment it lands, a blocked task yields a structured blocker with real options, everything poisoned by that blocker is `PARKED` rather than guessed at, and the run stops **once** with the whole batch — never mid-drain, never with a question no one can answer.

## Why this sprint

E5 is where the conductor stops writing documents and starts spending real money on real code, and it is the first stage whose failure mode is *silence*: an agent that cannot ask (invariant 2 / D4) and is stuck will, left alone, invent an answer and keep going. Drain-then-halt is the shape that makes that impossible — not by making the agent smarter, but by removing the situation in which guessing is the only move. Blocked means blocked; parked means "I did not touch this, and here is why"; and the escalation is one batched decision at the end, not a stall in the middle.

Refinement against live source found four things the backlog's rows could not know, and three of them are structural.

**The state spine cannot record a finished task.** `TaskStatus` has had `DONE`, `DONE_WITH_CONCERNS` and `PARKED` since S1 (`scripts/supskill_state/model.py:45-51`), and `TERMINAL_STATUSES` consumes all four (`model.py:54-56`) — but no CLI verb writes any of them. `tasks` loads `PENDING` (`commands.py:322-325`); `block` writes `BLOCKED` (`commands.py:269`); the subparser list is `init | show | artifact | gate | block | tasks | advance | plan-guard` (`cli.py:21-28`) and that is all of it. So a sprint whose every task succeeds can **never** reach REVIEW: `advance --to REVIEW` refuses while any task is non-terminal (`transitions.py:39-46`) and nothing can make a successful task terminal. SK-043 was scoped as a mapping ("map SDD's four statuses onto task status") — the mapping was never the missing half. The *verb* was.

**The SDD progress ledger is the scratch-dir collision, still alive.** D8 and SK-004 killed the collision for briefs and reports by deriving `.superpowers/sdd/<sprint-id>/` from the sprint id (`scripts/supskill_state/scratch.py:29-30`), and SDD's `task-brief` and `review-package` both take an `OUTFILE` third argument, exactly as the backlog promised. But SDD's *durable progress ledger* has no override: it is read and written at a hardcoded `<repo-root>/.superpowers/sdd/progress.md` (SDD SKILL.md:254-256), and its contract is "tasks listed there as complete are DONE — do not re-dispatch them", keyed by **task number**, which restarts every sprint. A ledger left behind by S5 tells S6's controller that S6's Task 1 is already complete. That is precisely the failure `scratch.py:3-7` was written to make structurally impossible, and it walks straight back in through a file supskill does not name. The resolution is not another path override — it is that **`state.json` is the ledger**, which it can only be if the conductor is the SDD controller.

**The derived scratch directory does not exist on disk, and the first `task-brief` will die on it.** `derive_scratch` returns a *string* — `.superpowers/sdd/<id>/` — and nothing creates it: `init` mkdirs `.supskill/runs/<id>/` and the gates trail and stops there (`commands.py:83-87`), and `scratch.py` has no filesystem call at all (`scratch.py:19-30`). SDD's `task-brief` with an explicit `OUTFILE` writes with a plain shell redirect and never mkdirs the parent (SDD scripts/task-brief, the `awk … > "$out"` line); its `sdd-workspace` helper — the *only* thing that creates the directory and drops the self-ignoring `.gitignore` that keeps SDD's scratch out of `git status` — is called **only on the default-OUTFILE path**. So the exact thing D8 asked for (always pass `OUTFILE`) is the exact thing that skips the directory's creation and its git-ignoring. In *this* repo the second half is masked: `.gitignore:9` already ignores `.superpowers/`. In the target repos supskill is built to drive, it is not — and an implementer running `git add -A` commits a sprint's briefs and diffs. Two one-line moves fix both, and they belong in the EXECUTE row: run SDD's `sdd-workspace` once (it mkdirs and writes the `*` ignore that covers every sprint subdir), then `mkdir -p <sprint.scratch>`.

**And that is the sprint's one real design decision.** SDD's controller loop is where every supskill-relevant fact appears: a task's status, a blocker's cause, a concern worth carrying to Gate 3. If the conductor dispatches SDD *into a subagent*, all of that lands behind a context boundary that cannot run `supskill-state` (invariant 3, `skills/supskill/SKILL.md:30-32`), cannot ask the operator anything (D4), and — per SDD's own instruction to "escalate to the human" on a bad plan — will find itself holding an empty answer with an entire sprint's autonomy in its hands. The conductor therefore **is** the controller: it invokes `superpowers:subagent-driven-development` in its own session (SDD's own decision tree calls this the same-session mode), dispatches a fresh implementer and reviewer per task exactly as SDD prescribes, and writes each status to disk as it lands. The fresh-context boundary the product promises is still there — it is per *task*, which is where SDD puts it — and the conductor's context stays lean because SDD hands artifacts over as files, not pasted text. This is the smaller, reversible choice: if it proves wrong, what moves is *where the loop runs*, not what the verbs do. The operator can overrule it at Gate 1.

## Capacity & sequencing

Working capacity ~**34 pts**; ~18% buffer → ~**28 pts committable** (the same model as S1–S4; this repo has one operator and one conductor — there is no roster, no PTO, no ceremony, and `sprint-plan`'s capacity checklist is reframed, not obeyed). Committed: **23 pts** — the largest sprint so far, and the one with the hardest single story in the backlog (SK-041). Five points of headroom stay unspent on purpose: E6's PAR is not pullable in halves, and SK-041 is the story most likely to want the slack.

- **Critical path:** SK-043's status verb (nothing terminal can be recorded without it) → SK-040 (the dispatch and the scratch/ledger discipline) → SK-041 (the drain loop, which consumes both) → SK-042 (the blocker's quality, which only matters once the loop can produce one).
- **Wave A (parallel, pure offline Python):** SK-043's `task --id … --status …` verb, its append-only `tasks.jsonl` trail, and its refusals. Independent of every line of prose in this sprint.
- **Wave B (prose, after wave A):** SK-040's EXECUTE row and dispatch discipline; SK-041's drain loop and halt report; SK-042's blocker-authoring rules.

SK-043 first is not a preference: SK-041's loop ends every task by calling the status verb, so writing the loop before the verb exists produces prose that describes a command that refuses.

## Stories

### SK-040 — Dispatch SDD, and own the scratch the ledger forgot · 7 · M · **(5 → 7 at pull time)**

- **As** the EXECUTE stage, **I want** `subagent-driven-development` driven from the conductor with every scratch artifact under this sprint's derived directory, **so that** the sprint's execution composes SDD verbatim (D1) and cannot collide with any other sprint's (D8).
- **proof:** seam=app-level · impact=cross-surface · provable=operator

- **Context.** The backlog's row is right about the mechanism and half-right about the surface. `task-brief PLAN_FILE N [OUTFILE]` and `review-package BASE HEAD [OUTFILE]` both accept the third-argument override (SDD scripts/task-brief and scripts/review-package, usage lines) — so briefs, reports and review packages all land under `sprint.scratch` (`scratch.py:29-30`, recorded at init and read from `show --json`). Three things the row could not see. (1) The **ledger** takes no override: SDD reads and writes `<repo-root>/.superpowers/sdd/progress.md` (SDD SKILL.md:246-258), keyed by task number, which restarts every sprint. supskill does not need a second ledger: `tasks[]` in `state.json` already *is* one, it is sprint-scoped by construction, and it is the file the conductor resumes from (invariant 5). So the conductor keeps SDD's ledger discipline and changes its medium — which it may only do because it is the controller. (2) **Passing `OUTFILE` is what skips the directory's creation**: SDD's `sdd-workspace` helper mkdirs `.superpowers/sdd/` and writes the `*` `.gitignore` that keeps SDD's scratch out of `git status`, and it runs only on the default path. `sprint.scratch` is a derived string, not a directory (`scratch.py:19-30`); `init` creates `.supskill/runs/<id>/` and the gates file and nothing else (`commands.py:83-87`). (3) SDD's own scratch already exists in this repo from S1–S4 — including a stale `progress.md` naming task numbers from a different sprint. That file is exactly the collision this story closes, and it is already sitting on disk.

- **Accept:**
  - The conductor invokes `superpowers:subagent-driven-development` **in its own session**, as the controller: fresh implementer subagent per plan task, task reviewer after each, fix subagent on Critical/Important findings, whole-branch review at the end. No supskill re-implementation of any of it (D1). Nested dispatch is fine — depth 2 of 5 (F-3).
  - **Prepare the scratch before the first dispatch, in this order:** run SDD's `sdd-workspace` (it mkdirs `.superpowers/sdd/` and writes the self-ignoring `.gitignore`, which covers every sprint subdir under it), then `mkdir -p <scratch>`. Without the first, a target repo that does not ignore `.superpowers/` lets an implementer's `git add -A` commit the sprint's briefs and diffs. Without the second, the very first `task-brief … <scratch>/task-1-brief.md` fails on the shell redirect, because `task-brief` does not create its `OUTFILE`'s parent. Neither is optional and neither is inferable from the backlog's row.
  - **Every** SDD scratch path is passed explicitly: `task-brief <plan> <N> <scratch>/task-<N>-brief.md`, report file `<scratch>/task-<N>-report.md`, `review-package <base> <head> <scratch>/review-<N>.diff`, where `<scratch>` is `sprint.scratch` read from `show --json` and never typed by hand (invariant 4). The report file is named after the brief, per SDD's File Handoffs rule (SDD SKILL.md:219-244) — so a re-read of a task's outcome is one `Read`, not a re-dispatch.
  - **`BASE` is recorded, never derived.** Before each implementer dispatch the conductor runs `git rev-parse HEAD` and keeps the SHA as that task's `BASE`; the review package is `review-package <BASE> HEAD …`. SDD forbids `HEAD~1` in as many words — it silently drops all but the last commit of a multi-commit task (SDD SKILL.md:136). The final whole-branch review gets `review-package $(git merge-base <default-branch> HEAD) HEAD …` (SDD SKILL.md:203-208). `sprint.branch` is optional at init (`cli.py:38`) and is *not* the authority here — `git` is.
  - **Every dispatch names its model explicitly.** SDD says an omitted model silently inherits the session's — usually the most capable and most expensive one (SDD SKILL.md:115-118). The EXECUTE row states this as a rule, not a suggestion, and leaves the per-task choice to SDD's own Model Selection section rather than restating it.
  - **The ledger is `state.json`.** The conductor does not read or write `.superpowers/sdd/progress.md`; it resumes from `tasks[]` — statuses beyond `PENDING` are complete and are never re-dispatched. A stale `progress.md` already exists in this repo (left by S1–S4); it is ignored and named once in the halt report so the operator can delete it. It is git-ignored scratch, not state.
  - **Branch check before the first dispatch.** SDD's own red flag is "never start implementation on main/master without explicit consent", and a subagent cannot obtain consent (D4). If `git rev-parse --abbrev-ref HEAD` is the repo's default branch, the conductor **stops before dispatching anything**, reports that EXECUTE writes commits and will not write them to the default branch, and names `git switch -c <branch>` as the operator's move. The conductor does not create, switch, or delete a branch — the same rule that keeps it from ever passing `--archive`.
  - **Exactly three places in `skills/supskill/SKILL.md` say EXECUTE is a stub, and all three change.** The dispatch-table row (`skills/supskill/SKILL.md:94`) becomes a pointer to a new `## The EXECUTE stage` section placed after Gate 2; the "EXECUTE and REVIEW are honest stubs" sentence (`skills/supskill/SKILL.md:97-98`) is narrowed to REVIEW alone; and Gate 2's approval step — which today reads "continue at the `EXECUTE` dispatch row (E5's honest stub: it reports and stops — do not improvise EXECUTE)" (`skills/supskill/SKILL.md:261-262`) — is rewritten to route into the real stage. Missing the third leaves the only path that *reaches* EXECUTE still instructing the conductor not to run it. A grep for `improvise EXECUTE` and `not implemented yet` over `skills/supskill/**` must come back empty at the end of this story; a test asserts it, so the contradiction cannot ship.

The template lint (`tests/test_prompt_templates.py:27`) therefore keeps its current three templates and gains no fourth — the invariant-3 assertion moves to SKILL.md's EXECUTE section instead.

### SK-041 — Drain-then-halt · 8 · M · **(8 → 8 at pull time — the only story refinement did not re-point; it gained two definitions, not scope)**

- **As** the operator, **I want** the conductor to run everything it *can* run, park everything it cannot, and then stop once with the whole batch, **so that** an agent that cannot ask a question never has a reason to guess (D4) and I get one high-information decision instead of a stall or a silent invention.
- **proof:** seam=app-level · impact=journey · provable=operator

- **Context.** This is the backlog's hardest story and the one the product is named for. It is also where two words needed a definition the backlog never gave.

  *"Downstream of a blocker"* is not computable from state: `Task` carries `id`, `seam`, `provable`, `status` and nothing else (`model.py:75-80`) — there is no dependency edge anywhere, and inventing one means either a schema change or a second parser over the dev plan. Both are bigger than this sprint needs. **The smaller, reversible choice: the conductor discovers downstream, it does not predict it.** It drains in plan order; when a task comes back `BLOCKED`, that task gets a blocker record and stops the *chain*, not the drain; a later task that reports `BLOCKED` **for the same root cause** (its report names the already-blocked story or the artifact that story was to produce) is recorded `PARKED`, not blocked again — one blocker per root cause, options enumerated once. The cost is honest and bounded: at most one wasted implementer dispatch per genuinely-dependent task, and the operator can overrule the whole approach at Gate 1 by asking for an explicit `depends:` declaration in the plan instead.

  *`provable`* (SK-022, the classification the backlog says "E5 cannot drain-then-halt without") is **not a run/skip filter** — every non-blocked, non-parked task runs. It decides what the halt report *claims*: an `offline` task's completion is asserted with the test command and its output; an `operator` task's completion is asserted as "implemented and reviewed; **not proven** — verify by hand", and it is listed for Gate 3 as such. Drain-then-halt without it would let the conductor report a journey-seam story as "done, tests green" — F-5's exact failure, one level up.

- **Accept:**
  - **The drain.** In plan order, for every task whose status is `PENDING`: dispatch the SDD cycle (implementer → task review → fix → status). Any task already terminal in `tasks[]` is skipped — never re-dispatched (SDD's ledger rule, on our ledger). After each task, its status is written to disk **before the next dispatch begins**: a `/clear` or a crash mid-drain loses at most one task's work, and re-invoking resumes at the first `PENDING` task from `state.json` alone (invariant 5).
  - **The halt.** The drain ends when no `PENDING` task remains. Then, exactly once, the conductor reports **one batch**: per task — status, commits, what its `provable` class does and does not claim; every blocker with its `found`, its `options[]` and its `recommend`; every parked task with the blocker that parked it; and every `DONE_WITH_CONCERNS` concern, verbatim. Then it stops. It does **not** advance to REVIEW, does not open a gate, and does not ask a question — E6 owns Gate 3, and until E6 lands, the halt report *is* the deliverable and the EXECUTE row says so.
  - **The halt is the target shape, not an error state.** A sprint that drains 4 of 6 tasks and halts with two blockers is a *successful* EXECUTE. The report says so in those words; nothing in the prose calls it a failure.
  - **Never guess.** The conductor does not: skip a task because it looks hard, mark a task `DONE` on an implementer's word alone (the task review is not optional — SDD's red flag), re-dispatch the same task with the same input twice, or invent a blocker's options. A situation with no legal move is a blocker (SK-042), and a blocker halts the chain — it never halts the *drain*.
  - **The pre-flight conflict scan** SDD runs before Task 1 (SDD SKILL.md:85-97 — its batched question to the human) has no one to ask here. Conflicts it finds are recorded as blockers on the affected tasks — with real options — and those tasks are parked. If the scan blocks every task, the drain runs nothing and the halt is immediate, which is correct and is not a crash.
  - **SDD's other two "ask the human" points become blockers, not guesses.** A reviewer finding labelled *plan-mandated*, or any finding that contradicts the plan's text, is the human's decision in SDD (SKILL.md:198-202): the conductor must not dismiss the finding because the plan mandated it, and must not dispatch a fix that contradicts the plan. It records a blocker whose `--found` is the finding beside the plan text that mandates it, and whose options are the two courses that actually exist — fix it against the plan, or keep the plan and carry the finding. A reviewer's "⚠️ cannot verify from diff" item is the opposite case: SDD requires the *controller* to resolve it (SKILL.md:150-158), and the conductor holds the plan and the cross-task context to do so — it resolves it or, if it cannot, blocks. Neither is a place where an empty answer may pass for a decision.
  - **`NEEDS_CONTEXT` is resolved in-loop, once.** It is not a persistable status by design (`model.py:133-146`): the conductor supplies the missing context and re-dispatches the same task **one** time. Still `NEEDS_CONTEXT` → it becomes `BLOCKED` plus a blocker record (D5). There is no unbounded loop anywhere in this stage.

### SK-042 — The blocker is a decision, not a shrug · 2 · M · **(3 → 2 at pull time)**

- **As** the operator reading a halt, **I want** every blocker to enumerate real options and name a recommendation I can disagree with, **so that** the batch is a decision I can make in one pass — and so that a *wrong* recommendation still leaves me the right option.
- **proof:** seam=app-level · impact=local · provable=operator

- **Context.** This story shrinks, and the shrink is the finding: **the enforcement already shipped in S1.** `record_blocker` refuses fewer than two options, refuses an unlabelled option, refuses a duplicate label, refuses a `recommend` that does not reference one of them, and refuses a task it cannot find (`commands.py:228-253`); it writes the trail before the state and flips the task to `BLOCKED` (`commands.py:257-269`). Nothing in the CLI is missing. What is missing is the *conductor's* half: turning an implementer's `BLOCKED` report into options that are genuinely different courses of action rather than three phrasings of "ask the operator". The remaining work is prose plus one fixture, and pretending otherwise would be padding.

- **Accept:**
  - SKILL.md's blocker rules, in the EXECUTE row: options are **materially different courses of action** (do X / do Y / stop and change the plan), each labelled `(a) …`; `--found` is what was **observed**, not what was inferred; `--recommend` names one option and says why in the same breath. Never fabricate an option to satisfy the CLI's two-option floor — if there is genuinely one move, there is no decision to escalate, and the task was not blocked.
  - **blinkebot's S9a blocker is the fixture**, verbatim from the backlog's row: the *recommended* option was wrong and option (c) was right. The test asserts that record survives `record_blocker`'s validation intact — including that a reader can still reach (c). A blocker format in which a wrong recommendation misleads the operator has failed at exactly the moment it mattered.
  - The recommendation is **advice, not a decision**: the conductor never acts on its own recommendation, at any point, for any reason. It halts. (D4 — escalation is out-of-band, always.)

### SK-043 — Record what SDD reported: the status verb and the mapping · 6 · M · **(3 → 6 at pull time)**

- **As** `advance --to REVIEW`, **I want** every finished task's SDD status durably on disk with its concerns in an append-only trail, **so that** REVIEW is reachable at all, and so that Gate 3 reads what actually happened rather than what the conductor remembers.
- **proof:** seam=unit · impact=cross-surface · provable=offline *(its SKILL.md mapping rows are seam=app-level · provable=operator; the story's bulk and all its risk are the offline verb)*

- **Context.** The backlog framed SK-043 as a mapping table, and the mapping is indeed trivial — SDD reports `DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT` and the state spine adopted that vocabulary verbatim (F-2, D5, `model.py:5-9`). The mapping is not the work. **The work is that no verb can write a status at all.** `cli.py:21-28` lists every subcommand: `init`, `show`, `artifact`, `gate`, `block`, `tasks`, `advance`, `plan-guard`. `tasks` writes `PENDING` (`commands.py:322-325`); `block` writes `BLOCKED` (`commands.py:269`); `DONE`, `DONE_WITH_CONCERNS` and `PARKED` are unreachable strings in an enum. Every task in a green sprint stays `PENDING` forever, `advance --to REVIEW` refuses forever (`transitions.py:39-46`), and the sprint cannot end. This is a *sprint-ending* defect that no row in the backlog names, found by reading `cli.py` — the fifth consecutive sprint where the refinement's sharpest finding is structural.

  Concerns need a home too, and a schema change is the wrong price for it. `DONE_WITH_CONCERNS` "proceeds but carries the concern to Gate 3" (D5) — and `Task` has no field for prose. The smaller choice, and the one the codebase already votes for: an **append-only trail**, exactly like `gates.jsonl` and `blockers.jsonl` (trail first, state second — `commands.py:209`, `commands.py:257-267`). No schema bump, no new field, and if E6 finds a trail insufficient, adding `Task.note` later is additive. Reversible either way.

- **Accept:**
  - `supskill-state task --id <SK-0xx> --status <DONE|DONE_WITH_CONCERNS|PARKED> [--note "<verbatim>"]`, TDD'd offline:
    - Refuses an id not in `tasks[]` — the same rule `record_blocker` already enforces (`commands.py:253`); a status that cannot attach to a known task is a typo or a hallucinated task, never a new one. This verb **never creates a task.**
    - Refuses `NEEDS_CONTEXT` with the model's own message (`model.py:133-146`) — it is a controller-loop signal, not a resting state.
    - Refuses `BLOCKED`: that transition belongs to `block`, which is the verb that also demands the options. A conductor that could set `BLOCKED` without a blocker record could halt with a shrug.
    - Requires `--note` for `DONE_WITH_CONCERNS` — a concern with no text is not a concern.
    - Writes `.supskill/runs/<normalized-sprint-id>/tasks.jsonl` **first** (`{task, status, note, at}`), then the state, per the trail-first rule (`scripts/supskill_state/commands.py:1-8`). Exact path and exact shape: the sibling of `blockers.jsonl`, built the same way — `store.runs_dir(root) / normalize_sprint_id(state.sprint.id) / "tasks.jsonl"` (`commands.py:256`), appended with `store.append_jsonl` (`store.py:64-70`) and timestamped with `store.now_utc_iso()` (`store.py:73-74`). The id is normalized, not the raw `sprint.id`; `runs_dir` is `.supskill/runs` (`store.py:37-38`). Re-recording a task's status is legal and appends: last status wins in state, every attempt stays in the trail. Gate 3 (E6) reads the trail; nothing re-parses prose.
    - `--note` is **optional on `DONE` and `PARKED`, required on `DONE_WITH_CONCERNS`** — and on `DONE` it is where SDD's Minor-findings roll-up lands. SDD tells the controller to record Minor findings in the ledger as it goes and to point the final whole-branch review at that list, because "a roll-up nobody reads is a silent discard" (SDD SKILL.md:193-197). Our ledger is `state.json` plus this trail, so the Minor findings of a task go into its `--note`, and the final review dispatch names the trail file. A `PARKED` note names the blocker that parked the task (SK-041).
  - SKILL.md's mapping rows in the EXECUTE loop, one line each: `DONE` → `task --status DONE`. `DONE_WITH_CONCERNS` → `task --status DONE_WITH_CONCERNS --note "<the implementer's concern, verbatim>"`; the drain continues and the concern surfaces in the halt batch. `BLOCKED` → `block …` (SK-042), which flips the status itself. `NEEDS_CONTEXT` → resolve in-loop once, else `block` (SK-041).
  - **The join is the plan task heading, and this sprint adds no parser.** SDD reports per plan task (`Task N`); `tasks[]` is story-shaped (`SK-0xx`); the heading `### Task N: <what> (SK-0xx)` is the only bridge, required by SK-030 and already validated at load time (`commands.py:314-320`). A plan task marked `(process)` maps to no story and no status call — it is the demo checklist, not a backlog row. Where several plan tasks serve one story, the story is `DONE` only when **all** of them are; any `DONE_WITH_CONCERNS` among them makes the story `DONE_WITH_CONCERNS`; any blocker among them blocks the story. Stated here because it is the one place a mapping can quietly lie.
  - Offline coverage both directions, including: every unreachable status becomes reachable (a full `PENDING → DONE → advance --to REVIEW` walk on a fixture state, which is impossible on `main` today).

## DoR findings (refined at pull time)

Fifth sprint refined against live source. Sprint goes **19 → 23 pts** (SK-043 3 → 6, SK-040 5 → 7, SK-042 3 → 2, SK-041 unchanged at 8).

1. **No verb can set a task to `DONE`** (grew SK-043 3 → 6). The subcommand list is `init | show | artifact | gate | block | tasks | advance | plan-guard` (`cli.py:21-28`). `DONE`, `DONE_WITH_CONCERNS` and `PARKED` exist in the enum (`model.py:45-51`) and in `TERMINAL_STATUSES` (`model.py:54-56`), and nothing writes them. A sprint in which every task succeeds can therefore never satisfy `advance --to REVIEW` (`transitions.py:39-46`). SK-043 was scoped as a mapping table; the mapping is four lines of prose. The missing thing was the verb, its trail, and its refusals.

2. **The SDD progress ledger reopens the collision D8 closed** (grew SK-040). `task-brief` and `review-package` take `OUTFILE` exactly as the backlog says — but the ledger at `<repo-root>/.superpowers/sdd/progress.md` (SDD SKILL.md:246-258) has no override, is keyed by task number, and task numbers restart every sprint. Its contract ("tasks listed complete are DONE — do not re-dispatch") means a stale S5 ledger tells S6's controller that S6's Task 1 is finished. `scratch.py:3-7` exists to make exactly this impossible. The file is not hypothetical: a `progress.md` from S1–S4 is on disk in this repo right now. Resolution: the conductor does not use SDD's ledger — `state.json`'s `tasks[]` is the ledger, sprint-scoped by construction, and the resume path already reads it.

3. **The conductor is the SDD controller — a decision the backlog left implicit.** "Dispatch SDD" reads naturally as "hand SDD to a subagent", and that placement is wrong in a way that is hard to reverse later: the controller loop is where statuses, blockers and concerns appear, and a subagent controller cannot run `supskill-state` (invariant 3), cannot ask the operator anything (D4), and is instructed by SDD to "escalate to the human" it does not have. Everything E5 must record would land behind a boundary that cannot record it — and drain-then-halt would become drain-then-report-a-summary, which is the self-certification F-5 warns about. The conductor runs the loop itself, in the same session SDD's own decision tree prescribes; the fresh-context boundary stays where SDD puts it, per task. Reversible: what would move is the loop's location, not the verbs.

4. **"Downstream of a blocker" is not computable from state** (shaped SK-041, points unchanged). `Task` has no dependency edge (`model.py:75-80`), and adding one means a schema change plus a plan parser. The sprint takes the smaller path: downstream is **discovered, not predicted** — a task that itself reports `BLOCKED` naming an already-blocked root cause is `PARKED` rather than double-blocked. Cost: at most one wasted dispatch per truly-dependent task. Named in the risks table so the operator can overrule it at Gate 1 in favour of an explicit `depends:` declaration.

5. **`provable` is not a run/skip filter** (clarified SK-041). SK-022 said "E5 cannot drain-then-halt without this", which reads like a gate on execution. It is a gate on *claims*: every drainable task runs, and `provable` decides whether the halt report says "proven, here is the command and its output" or "implemented and reviewed, **not proven** — verify by hand". Without it the conductor would report a journey-seam story as green because its unit tests passed.

6. **SK-042 shrinks, and that is a finding, not a discount** (3 → 2). Every structural rule the story asks for shipped in S1: two-option floor, labelled options, a `recommend` that must reference one of them, a task that must exist (`commands.py:228-253`). What remains is the conductor's authoring discipline and the blinkebot S9a fixture. Points move to where the risk actually is (SK-043's verb). Recorded so nobody re-inflates it out of ritual.

7. **EXECUTE writes commits, and a subagent cannot consent to writing them to `main`** (folded into SK-040). SDD's red-flag list forbids starting implementation on the default branch without explicit consent; `sprint.branch` is optional at init and nothing enforces it. The conductor checks the current branch before the first dispatch and stops if it is the default one — naming `git switch -c` without running it, the same discipline that keeps `--archive` out of its hands.

8. **The derived scratch directory is a string, not a directory — and the first `task-brief` dies on it** (grew SK-040 6 → 7, together with findings 9 and 10). `derive_scratch` computes `.superpowers/sdd/<id>/` and returns it (`scratch.py:19-30`); nothing calls `mkdir`. `init` creates `.supskill/runs/<id>/` and touches the gates trail, and stops (`commands.py:83-87`). SDD's `task-brief`, given an explicit `OUTFILE`, writes with a bare shell redirect (`awk … > "$out"`) and never creates the parent — so the very first dispatch of the very first EXECUTE run fails on "No such file or directory". Worse, the helper that *would* have created it — SDD's `sdd-workspace` — is also the only thing that writes the self-ignoring `.gitignore` keeping SDD's scratch out of `git status`, and it runs **only** on the default-`OUTFILE` path that D8 forbids us. This repo masks the second half (`.gitignore:9` already ignores `.superpowers/`); a target repo will not, and an implementer's `git add -A` will commit a sprint's briefs and diffs. Resolution, both one-liners in the EXECUTE row before the first dispatch: run `sdd-workspace`, then `mkdir -p <sprint.scratch>`. **Recommended answer for the operator:** take both; the alternative (teach `init` to mkdir the scratch dir) puts a filesystem side-effect into a pure derivation and still does not solve the `.gitignore`.

9. **Three surfaces in SKILL.md call EXECUTE a stub, and the backlog's row implies one** (grew SK-040). The dispatch-table row (`skills/supskill/SKILL.md:94`) is the obvious one. But the prose beneath it (`skills/supskill/SKILL.md:97-98`) also says "EXECUTE and REVIEW are honest stubs", and — the one that actually bites — Gate 2's approval step tells the conductor to "continue at the `EXECUTE` dispatch row (E5's honest stub: it reports and stops — do not improvise EXECUTE)" (`skills/supskill/SKILL.md:261-262`). Gate 2's approval is the *only* path that reaches EXECUTE. A sprint that rewrites the dispatch row and forgets line 261 ships a conductor that builds the whole stage and is then told not to run it. Resolution: all three change in SK-040, and a test greps `skills/supskill/**` for `improvise EXECUTE` and `not implemented yet` — the second must survive only for REVIEW.

10. **SDD's `BASE`, its model rule, and its two remaining "ask the human" points** (grew SK-040 and shaped SK-041; no new points on 041). Refinement against the installed skill (superpowers 6.1.1) turned up four composed contracts the backlog's one-liner could not carry: `BASE` must be the SHA recorded *before* each implementer dispatch, never `HEAD~1`, which silently drops all but the last commit of a multi-commit task (SDD SKILL.md:136); the final whole-branch review takes a `merge-base` package of its own (SDD SKILL.md:203-208); every subagent dispatch must name its model explicitly or it silently inherits the session's most expensive one (SDD SKILL.md:115-118); and beyond the pre-flight scan, SDD sends the human *two* more decisions — a plan-mandated review finding (SKILL.md:198-202) and, differently, a reviewer's "⚠️ cannot verify from diff" item the controller must resolve itself (SKILL.md:150-158). In supskill the first is a blocker with two real options; the second the conductor resolves, or blocks. **Recommended answer:** as written. There is no third path — an agent that cannot ask and will not block is an agent that guesses, which is the one thing this sprint exists to prevent.

**Deliberately NOT in scope**, though tempting: Gate 3 and the batched decision surface (E6 — the halt report is this sprint's deliverable and it stops there), PAR (E6), the replan shapes and generative writeback (E6), a `depends:` field or dependency graph in the schema (finding 4 — discovery instead), a sandbox that makes an implementer's edits reversible (F-4's ceiling: loud and auditable, not impossible), multi-sprint drain (SK-091, parked), and any "continue anyway" affordance past a blocker (drain-then-halt is the product).

Two of this pass's ten findings are things that would have failed on the *first command of the first run* (the scratch directory that does not exist; Gate 2 still forbidding the stage it now opens), and neither is visible from anywhere but the source. Five sprints, five data points, same direction. §7.2's answer at E6 stands: *the gate earns its keep because the refinement does.*
